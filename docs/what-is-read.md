# What ifinjected reads

Every path a scan may look at is declared here, with how deep it looks. A contract test
records every look during whole scans and fails on any path that is not declared, or on
a deeper look than declared. This file is generated from the catalog
(`uv run python -m ifinjected.inventory.docs`); a test fails when the two differ.

## Why each item matters

- **SSH private key**: Logs in to every server and pushes to every Git host that trusts the key. Without a passphrase, the file alone is enough. Sources: [ssh(1): FILES, the default identity files in ~/.ssh](https://man.openbsd.org/ssh#FILES), [OpenSSH PROTOCOL.key: the private key format and its cipher field](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.key).
- **SSH public key**: Public. Read to name the private key next to it by its type and fingerprint. Sources: [ssh-keygen(1): key files, passphrases and fingerprints](https://man.openbsd.org/ssh-keygen).
- **AWS credentials file**: Static access keys work from anywhere until someone rotates them. Sources: [AWS CLI: configuration and credential file settings](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html).
- **AWS config**: Can hold access keys too, and names the roles and SSO sessions every profile can use. Sources: [AWS CLI: configuration and credential file settings](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html).
- **AWS cached session tokens**: Short-lived, but valid for hours: enough to copy everything a role can read. Sources: [AWS CLI: IAM Identity Center (SSO) token cache](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html).
- **Google Cloud CLI credentials**: Refresh tokens for every account gcloud is signed in to; they do not expire on their own. Sources: [gcloud CLI: managing configurations (CLOUDSDK_CONFIG and the config directory)](https://cloud.google.com/sdk/docs/configurations).
- **Google application default credentials**: Every Google client library on the machine uses this file: a refresh token or a service account key. Sources: [Google Cloud: how Application Default Credentials works](https://cloud.google.com/docs/authentication/application-default-credentials).
- **Azure CLI tokens and service principal secrets**: Signed-in sessions, and on Linux service principal secrets in plain JSON. Sources: [Azure CLI: sign in, token caching and AZURE_CONFIG_DIR](https://learn.microsoft.com/en-us/cli/azure/azure-cli-configuration).
- **GitHub CLI login**: A GitHub token with the scopes you granted gh: push, create repositories, read private code. In the keyring, `gh auth token` still prints it to anyone running as you. Sources: [GitHub CLI: gh auth login, credential storage in the system keyring or hosts.yml](https://cli.github.com/manual/gh_auth_login), [GitHub CLI: environment variables (GH_CONFIG_DIR)](https://cli.github.com/manual/gh_help_environment).
- **Git credential store**: Plain-text passwords and tokens for every Git host listed in it. Sources: [git-credential-store: credentials stored in plain text](https://git-scm.com/docs/git-credential-store).
- **netrc passwords**: Plain-text logins that curl, git and package managers use without asking. Sources: [curl: .netrc, the file and the NETRC variable](https://everything.curl.dev/usingcurl/netrc.html).
- **npm token**: Publishes packages under your name: a supply-chain attack waiting for one command. Sources: [npm: .npmrc files and auth-related configuration](https://docs.npmjs.com/cli/v11/configuring-npm/npmrc).
- **PyPI token**: Publishes packages under your name. Sources: [PyPA: the .pypirc file](https://packaging.python.org/en/latest/specifications/pypirc/).
- **Cargo registry token**: Publishes crates under your name. Sources: [Cargo: credentials (CARGO_HOME/credentials.toml)](https://doc.rust-lang.org/cargo/reference/config.html#credentials).
- **Docker registry logins**: Without a credential store, registry passwords sit in config.json, base64-encoded: push images as you. Sources: [Docker CLI: config.json, credential stores and helpers](https://docs.docker.com/reference/cli/docker/login/#credential-stores).
- **Kubernetes config**: Cluster access with your rights, often cluster-admin on development clusters. Sources: [Kubernetes: organizing cluster access using kubeconfig files](https://kubernetes.io/docs/concepts/configuration/organize-cluster-access-kubeconfig/).
- **Hugging Face token**: Reads private models and datasets, and with write scope pushes to them. Sources: [huggingface_hub: environment variables (HF_TOKEN_PATH, HF_HOME, XDG_CACHE_HOME)](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables).
- **Supabase access token**: Manages every Supabase project of the account: databases, keys, functions. Sources: [Supabase CLI: supabase login (falls back to ~/.supabase/access-token)](https://supabase.com/docs/reference/cli/supabase-login).
- **Terraform Cloud token**: Runs plans and applies, and reads state, which often holds more secrets. Sources: [Terraform: terraform login saves the token in plain text in credentials.tfrc.json](https://developer.hashicorp.com/terraform/cli/commands/login).
- **Vault token**: Reads every secret its policies allow, from the place you keep secrets. Sources: [Vault: the default token helper stores the token in ~/.vault-token](https://developer.hashicorp.com/vault/docs/commands/token-helper).
- **pass password store**: Encrypted with gpg; while gpg-agent holds the key, any process running as you can decrypt it. Sources: [pass: the standard unix password manager (~/.password-store, gpg)](https://www.passwordstore.org/).
- **1Password CLI**: With the app integration, `op` reads items as long as the app is unlocked. Sources: [1Password CLI reference: configuration directory and app integration](https://developer.1password.com/docs/cli/reference/).
- **Browser session cookies**: A copied cookie database signs in to every site you are signed in to, without a password or a second factor. Sources: [Chromium: user data directory locations per system](https://chromium.googlesource.com/chromium/src/+/main/docs/user_data_dir.md), [Chromium on Linux: how stored secrets are encrypted with a key from the keyring](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/password_storage.md), [Firefox: profiles, where Firefox stores your user data](https://support.mozilla.org/en-US/kb/profiles-where-firefox-stores-user-data).
- **Coding agent login token**: The agent's own account: an injected agent can send the token away and keep using your subscription or API key. Sources: [Claude Code: settings, credentials storage and local transcripts](https://code.claude.com/docs/en/settings), [Codex: configuration reference (CODEX_HOME, auth.json)](https://learn.chatgpt.com/docs/config-file/config-reference), [Gemini CLI: configuration reference (~/.gemini)](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [opencode: config and data locations](https://opencode.ai/docs/config/), [Copilot CLI: config directory reference (providers.json, session-state)](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference).
- **Coding agent transcripts and history**: Plain text that keeps whatever tools printed, including secrets read in earlier sessions. Sources: [Claude Code: settings, credentials storage and local transcripts](https://code.claude.com/docs/en/settings), [Codex: configuration reference (CODEX_HOME, auth.json)](https://learn.chatgpt.com/docs/config-file/config-reference), [Copilot CLI: config directory reference (providers.json, session-state)](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference).
- **.env file**: Application secrets for the project at hand: database passwords, API keys, signing secrets. Sources: [dotenv: .env files hold environment-specific secrets and are not committed](https://github.com/motdotla/dotenv#readme).
- **Secret-looking environment variables**: Inherited by every process the agent starts; one `env` command prints them all. Sources: [Google Cloud: GOOGLE_APPLICATION_CREDENTIALS names a credential file](https://cloud.google.com/docs/authentication/application-default-credentials#GAC).
- **ssh-agent socket**: Signs with every loaded key: log in and push as you without ever reading a key file. Sources: [ssh-agent(1): holds private keys and signs on behalf of clients of SSH_AUTH_SOCK](https://man.openbsd.org/ssh-agent).
- **Docker socket**: Whoever can write to it can start a container that mounts the whole disk: root on the machine. Sources: [Docker: the docker group grants privileges equivalent to root](https://docs.docker.com/engine/security/#docker-daemon-attack-surface).
- **gpg-agent socket**: Decrypts and signs for any client while a passphrase is cached. Sources: [GnuPG: gpg-agent caches passphrases and decrypts for its clients](https://www.gnupg.org/documentation/manuals/gnupg/Invoking-GPG_002dAGENT.html).
- **Coding agent configuration**: Read as data, never run: it decides what the agent may do. Not a secret by itself, though values such as MCP environment variables are dropped while parsing. Sources: [Claude Code: settings files and precedence](https://code.claude.com/docs/en/settings), [Codex: configuration reference (profile files next to config.toml)](https://learn.chatgpt.com/docs/config-file/config-reference), [Gemini CLI: policy engine (policies/*.toml)](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/policy-engine.md).
- **Sandbox programs**: Whether an agent's OS sandbox can run here is decided by whether its program exists; it is never run. Sources: [Claude Code: sandboxing, platforms and dependencies (bubblewrap on Linux)](https://code.claude.com/docs/en/sandboxing).
